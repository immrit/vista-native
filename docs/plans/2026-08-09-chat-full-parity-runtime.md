# Vista Native full Chat parity and runtime closure

**Type:** feature
**Status:** in-progress
**Progress:** `[█████████░] 90%` (53/59)

## Problem / Goal
Native currently has a tested but partial Chat foundation in this worktree while
the main checkout contains a conflicting simplified inbox that misreads the
backend profile fields and has no production message screen. Deliver a
Flutter-parity, authenticated, cache-first Native Chat and prove it with the
same real account/content on the owned emulator.

## Root cause / Design
Flutter is the read-only behavior and visual source. The correct implementation
extends the existing feature-local `:feature:chat` stack and preserves
`Compose -> ViewModel -> Repository -> Room/Retrofit/OkHttp`. Conversation
identity comes from the backend `name`, `image`, `peer_id`, and
`conversation_type` contract with compatible aliases; realtime shares the
session/TLS policy and local plaintext never bypasses encryption boundaries.

- Flutter `E:\vista` is read-only; do not edit, format, build-generate, or clean it.
- Flutter runtime identity is permanently `ir.coffevista.vista`; no Native flavor may claim it. Native production/beta use `ir.coffevista.vista_native`, while isolated runtime builds may use an explicit suffix such as `ir.coffevista.vista_native.chat01`.

- Native main is dirty and contains unrelated work. Never reset, stash, clean, broadly stage, or overwrite it.
- Existing secret-chat history stays locked in Native because the Flutter X25519 private key is sandboxed; ciphertext is never rendered or sent as plaintext.
- Supplied credentials are used only through the emulator UI and never stored in commands, files, logs, fixtures, or evidence.
- Raw private screenshots remain local and untracked. Only final evidence intended for the user is retained.
